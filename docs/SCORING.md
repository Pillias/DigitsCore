# 누적 코어 지수 (Cumulative Score Model v2)

계산: `CumulativeScoreEngine`, 타임라인 전이: `CumulativeTimeline`, 영속 저장: `CumulativeScoreStore`.
제품 내부 사용 균형 지표이며 의료적 평가나 실제 인구 평균이 아닙니다. [이전 모델 4](SCORING_LEGACY_V4.md)는 호환용입니다.

## 핵심 원칙 및 동작

- **기준 균형점**: 75.0점 (신규 시작 75점, 표시 범위 1–99). 업데이트는 마지막 표시 점수를 유지합니다.
- **연속 상태 보존**: 점수, 사용 가속 잔여(momentum), 누적 회복 부담(burden)을 기기 내 암호화 DB에 보관합니다. 자정/24시간/48시간 임의 초기화는 없습니다.
- **통계와 점수의 분리**: 24시간/일별/주별은 조회 기간일 뿐이며 점수의 만료 기간이 아닙니다.
- **일반 / 관리 2단계 등급**: 
  - 동영상·SNS·숏폼·게임 등 무한 스크롤 및 몰입형 앱은 기본 '관리' 등급.
  - 업무·교육·쇼핑·음악 등은 '일반' 등급.
  - 내비게이션, 통화 등 필수 시스템 도구는 감점 면제(Exempt).
- **단일 휴식 모델 (화면 OFF 회복 일원화)**:
  - 수면 구간을 휴리스틱(23–07시 추정, 걸음 센서, 뒤척임 롤백 등)으로 별도 분리하지 않습니다.
  - 밤이든 낮이든 **화면이 꺼져 있는 동안은 뇌가 스마트폰 자극으로부터 쉬고 있는 상태**로 동일하게 취급되어 점수가 완만하게 회복됩니다.
  - 기존의 "수면 중 회복 중단/동결" 철학에서 발생하는 야간 근무자 오판 및 저득점 고착 문제를 원천 해결했습니다.
- **습관성 확인 보호**: 15초 이하의 짧은 확인은 사용 시간 가속을 유발하지 않으며, 열기 감점만 작게 반영합니다. 연속된 짧은 재진입은 1분을 넘길 때부터 일반 사용으로 누적합니다.

## 하루 최대 가동폭 및 스케일러 구조

기준점이 50점에서 **75점**으로 변경됨에 따라 상방 여유 공간(25점)과 하방 여유 공간(75점)이 비대칭 구조를 이룹니다.
75점 기준점에서도 "하루 표준적인 절제 생활 시 +10점 상승, 과도한 몰입 시 -10점 하락"이라는 표준 일일 가동폭($M = 10$점)을 유지하도록 상·하방 가동 배율이 설계되었습니다:

- **상방 일일 최대 가동폭**: $(100 - S) \times 40\%$
  - $S = 75$점일 때: $(100 - 75) \times 40\% = +10.0$점
  - $S = 30$점일 때: $(100 - 30) \times 40\% = +28.0$점 (강력한 반등 헤드룸)
  - $S = 90$점일 때: $(100 - 90) \times 40\% = +4.0$점 (과도한 99점 쏠림 방지)
- **하방 일일 최대 가동폭**: $S \times 13.33\%$
  - $S = 75$점일 때: $75 \times 13.33\% = -10.0$점
  - $S = 30$점일 때: $30 \times 13.33\% = -4.0$점 (하방 지지 저항)
  - $S = 90$점일 때: $90 \times 13.33\% = -12.0$점 (하강 중력)

### 속도 조절자 (Scalers)
- `speedUp() = ((100.0 - s) / 25.0).coerceIn(0.1, 4.0)`
- `speedDown() = (s / 75.0).coerceIn(0.1, 2.0)`

## 계수 및 파라미터 (CumulativeScoreConfig v2)

| 항목 | 값 | 설명 |
|---|---:|---|
| 기준 균형점 (`targetEquilibriumScore`) | 75.0 | 기본 목표 상태 |
| 일반 분당 기본 감점 (`normalLossPerMinute`) | 0.014 | 일반 앱 사용 손실 |
| 관리 분당 기본 감점 (`managedLossPerMinute`) | 0.055 | 몰입 관리 앱 사용 손실 |
| 기본 휴식 분당 회복 (`baseRestPerMinute`) | 0.0075 | 화면 OFF 시 기본 회복 속도 |
| 열기(오픈) 손실 (`openingLoss`) | 0.05 | 앱 실행 시 순간 비용 |
| 관리 가속 시작 / 단계 | 30분 / 15분 | 30분 초과 시 15분마다 18% 추가 감점 (최대 3배) |
| 일반 가속 시작 / 단계 | 60분 / 30분 | 60분 초과 시 30분마다 15% 추가 감점 (최대 2배) |
| 회복 부담 반감기 (`burdenHalfLifeAwakeHours`) | 2.0시간 | 연속 몰입으로 쌓인 부담의 자연 감소 주기 |
| 회복 감쇄 인자 (`burdenRecoveryDivisor`) | 3.0 | 부담이 휴식 회복을 억제하는 비율 |

## 회복 공식
화면이 꺼진 휴식 시간($dt$ 분) 동안 점수 변화량:
$$\Delta s = \frac{\text{baseRestPerMinute}}{1.0 + \frac{b}{\text{burdenRecoveryDivisor}}} \times \text{speedUp}(s) \times dt$$
- 누적 회복 부담($b$)이 클수록 회복 속도가 억제되며, 시간이 지나 부담이 반감기(2시간)를 거쳐 소멸하면 최고 효율로 회복됩니다.
- 점수가 낮을수록($s < 75$) `speedUp()`이 커져 빠르게 75점을 향해 반등하며, 80점 이상에서는 완만하게 수렴합니다.

## 기록과 이전

- DB 스키마는 기존 기록을 보존하며 하위 호환됩니다.
- 백업에 체크포인트가 포함되며, 복원 시 오프라인 시간은 회복으로 계산하지 않습니다.
