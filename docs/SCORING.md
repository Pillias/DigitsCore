# 누적 코어 지수 (Cumulative Score Model v3)

계산: `CumulativeScoreEngine`, 타임라인 전이: `CumulativeTimeline`, 영속 저장: `CumulativeScoreStore`.
제품 내부 사용 균형 지표이며 의료적 평가나 실제 인구 평균이 아닙니다. [이전 모델 4](../archive/docs/SCORING_LEGACY_V4.md)는 호환용입니다.

## 핵심 원칙 및 동작

- **기준 균형점**: 75.0점 (신규 시작 75점, 표시 범위 1–99). 업데이트는 마지막 표시 점수를 유지합니다.
- **연속 상태 보존**: 점수, 사용 가속 잔여(momentum), 누적 회복 부담(burden)을 기기 내 암호화 DB에 보관합니다. 자정/24시간/48시간 임의 초기화는 없습니다.
- **통계와 점수의 분리**: 24시간/일별/주별은 조회 기간일 뿐이며 점수의 만료 기간이 아닙니다. 논리적 하루 경계는 오전 `05:00`을 기준으로 합니다.
- **4단계 앱 등급 (`AppGrade`: 권장 / 필수 / 일반 / 관리)**:
  - **권장 (`FOCUS`)**: 공부·독서 앱 (`EXEMPT`, `isStudy = true`). 연속 50분까지 감점이 없으며(독립 카운터 `studyMomentumMinutes`), 50분 도달 시 초록불 눈 휴식 알림 후 일반 감점으로 전환됩니다.
  - **필수 (`TOOL`)**: 필수 유틸리티·금융·도구 (`EXEMPT`, `isStudy = false`). 연속 30분까지 감점이 없으며(`exemptMomentumMinutes`), 이후 일반 감점이 적용됩니다. 내비게이션·통화 앱은 시간 제한 없이 면제됩니다.
  - **일반 (`DAILY`)**: 메신저(카카오톡, 라인, 텔레그램, 슬랙 등), 업무, 음악, 일반 도구 (`NEUTRAL`). 가속 없이 기본 사용 부하만 적용됩니다.
  - **관리 (`LIMIT`)**: 동영상·SNS·숏폼·게임·웹툰 및 **쇼핑** 앱 (`DISTRACTING`). 연속 30분 초과 시 15분마다 감점이 가속되며 빨간불 과몰입 알림이 작동합니다.
- **보상은 점수에 개입하지 않습니다**: v0.9.40부터 15분 자유권을 연속 기록 보호권으로 바꿨습니다. 보호권은 연속 기록만 지키며 감점·가속·경고를 면제하지 않습니다. 서비스의 자유권 면제 분기는 이전 버전에서 이미 활성화된 구간이 끝날 때까지만 남아 있습니다.
- **주간 휴식과 수면 회복의 차등화 (RestPhasePolicy 연동)**:
  - 주간 깨어 있는 화면 OFF 휴식(`AWAKE_REST`): 180분(`awakeRestCapMinutes`) 이내에서는 시간당 +0.57점(`baseRestPerMinute = 0.0095` @75점)의 고회복을 적용합니다.
  - 야간 수면(`SLEEP`) 및 180분 초과 연속 미사용: 장기 방치 및 수면 상태로 간주하여 시간당 +0.27점(`sleepRestorationRate = 0.0045` @75점)의 완만한 회복률을 적용합니다.
  - 휴식 중 피로도(`useMomentumMinutes`)는 분당 -2.0(`momentumRestDecayRate = 2.0`) 배율로 빠르게 감소하여 휴식 후 즉각적인 재가속을 방지합니다.
  - 일반 앱 사용 시에는 피로도를 누적하지 않고 1.0배 기본 감점(`normalLossPerMinute = 0.012`)만 적용합니다.
- **앱 열기 감점 폐지**: 앱 진입/전환 시 부과되던 이중 처벌 감점을 완전 폐지(`openingLoss = 0.0`)했습니다.

## 하루 최대 가동폭 및 스케일러 구조

기준점이 50점에서 **75점**으로 변경됨에 따라 상방 여유 공간(25점)과 하방 여유 공간(75점)이 비대칭 구조를 이룹니다.
75점 기준점에서도 "하루 표준적인 절제 생활 시 +10점 상승, 과도한 몰입 시 -10점 하락"이라는 표준 일일 가동폭($M = 10$점)을 유지하도록 상·하방 가동 배율이 설계되었습니다:

- **상방 일일 최대 가동폭**: $(100 - S) \times 40\%$
  - $S = 75$점일 때: $(100 - 75) \times 40\% = +10.0$점
  - $S = 30$점일 때: $(100 - 30) \times 40\% = +28.0$점 (강력한 반등 헤드룸)
  - $S = 90$점일 때: $(100 - 90) \times 40\% = +4.0$점 (과도한 99점 쏠림 방지)
- **하방 일일 최대 가동폭**: $S \times 13.33\%$
  - $S = 75$점일 때: $75 \times 13.33\% = -10.0$점
  - $S = 30$점일 때: $30 \times 13.33\% = -4.0$점 (하방 지지 저항)
  - $S = 90$점일 때: $90 \times 13.33\% = -12.0$점 (하강 중력)

### 속도 조절자 (Scalers)
- `speedUp() = ((100.0 - s) / 25.0).coerceIn(0.1, 4.0)`
- `speedDown() = (s / 75.0).coerceIn(0.1, 2.0)`

## 계수 및 파라미터 (CumulativeScoreConfig v2)

| 항목 | 값 | 설명 |
|---|---:|---|
| 기준 균형점 (`targetEquilibriumScore`) | 75.0 | 기본 목표 상태 |
| 일반 분당 기본 감점 (`normalLossPerMinute`) | 0.012 | 일반 앱 사용 손실 (시간당 -0.72점) |
| 관리 분당 기본 감점 (`managedLossPerMinute`) | 0.042 | 관리 앱 사용 손실 (기본 시간당 -2.52점) |
| 주간 기본 휴식 분당 회복 (`baseRestPerMinute`) | 0.0095 | 주간 180분 이내 화면 OFF 시 회복 속도 (시간당 +0.57점 @75점) |
| 수면 분당 회복 (`sleepRestorationRate`) | 0.0045 | 수면 및 180분 초과 장기 미사용 시 회복 속도 (시간당 +0.27점 @75점) |
| 열기(오픈) 손실 (`openingLoss`) | 0.0 | 앱 실행 시 순간 비용 (이중 감점 폐지) |
| 관리 가속 시작 / 단계 | 30분 / 15분 | 30분 초과 시 15분마다 18% 추가 감점 (최대 2.2배) |
| 관리 최대 가속 배율 (`maxManagedMultiplier`) | 2.2 | 관리 앱 연속 사용 최대 가속 한도 |
| 휴식 시 피로도 감쇄율 (`momentumRestDecayRate`) | 2.0 | 화면 OFF 1분당 피로도(useMomentumMinutes) 2분씩 해소 |
| 주간 고회복 제한 시간 (`awakeRestCapMinutes`) | 180.0분 | 연속 미사용 180분 초과 시 수면 회복률로 전환 |
| 회복 부담 반감기 (`burdenHalfLifeAwakeHours`) | 2.0시간 | 연속 몰입으로 쌓인 부담의 자연 감소 주기 |
| 회복 감쇄 인자 (`burdenRecoveryDivisor`) | 3.0 | 부담이 휴식 회복을 억제하는 비율 |

## 회복 공식
화면이 꺼진 휴식 시간($dt$ 분) 동안 점수 변화량:
$$\Delta s = \frac{\text{restRate}}{1.0 + \frac{b}{\text{burdenRecoveryDivisor}}} \times \text{speedUp}(s) \times dt$$
- $\text{restRate}$는 연속 미사용 시간 $r < 180$분일 때 주간 고회복 `baseRestPerMinute`(0.0095), 수면 중이거나 $r \ge 180$분일 때 수면 회복률 `sleepRestorationRate`(0.0045)가 적용됩니다.
- 누적 회복 부담($b$)이 클수록 회복 속도가 억제되며, 시간이 지나 부담이 반감기(2시간)를 거쳐 소멸하면 최고 효율로 회복됩니다.
- 점수가 낮을수록($s < 75$) `speedUp()`이 커져 빠르게 75점을 향해 반등하며, 80점 이상에서는 완만하게 수렴합니다.

## 잠금 해제 간격 (v3, DEBATE 안건 18)
잠금 해제 1회마다 직전에 화면을 꺼 둔 시간 $g$로 판정합니다(`UnlockPacingPolicy`). 기준 $T_0$ = 12분(시간당 5회, 하루 약 100회).

| $g$ | 점수 변화 |
| --- | --- |
| 10초 미만 | 없음 (자동 꺼짐 직후 바로 켬) |
| 10초 ~ $T_0$ | $-0.05 \times (1 - g/T_0) \times \text{speedDown}(s)$ |
| $T_0$ ~ $2T_0$ | $+0.02 \times (g - T_0)/T_0 \times \text{speedUp}(s)$ |
| $2T_0$ 이상 | $+0.02 \times \text{speedUp}(s)$ (상한, 오래 쉰 것은 휴식 회복이 보상) |

- 화면이 켜진 시간(게임·영상)에는 잠금 해제가 없으므로 영향이 없습니다.
- 뉴트럴: 수면 뒤 첫 잠금 해제, 잠금 해제 직후 첫 앱이 통화·내비게이션, 직전 사용을 모르는 첫 정산.
- 하루(05:00) 합계 상한: 감점 −3P, 가점 +1P. 장부(`UnlockPacingLedger`)는 체크포인트와 함께 저장됩니다.
- 실제 잠금 해제 이벤트(보관 25시간)만 씁니다. 그보다 오래된 구간을 다시 계산하면 잠금 해제 영향은 0입니다.
- 75P 기준 예: 하루 100회 고르게 0P · 1시간 20회 −0.75P · 하루 150회 −2.5P · 2시간 쉬고 켬 +0.02P(+휴식 약 +1.1P).
- 감점·가점은 `score_impact_hourly`의 `#unlock` 키에 따로 남아 대시보드 요약 칸(앱 사용·잠금 해제·쉼)의 ±P가 됩니다.

## 기록과 이전

- **점수 모델 버전 관리 (`ScoreModel`)**: 저장소(DB·통계·백업)에 기록하는 현재 누적 모델(75점 피벗 + 잠금 해제 간격, 계산 설정 v3)의 저장 버전 번호는 `6`(`ScoreModel.CURRENT_STORED`)입니다. v2는 `5`입니다. 계수 미세 조정은 모델 번호를 올리지 않으며, 기준점·감점/회복 구조처럼 점수의 의미가 바뀌는 메이저 변경 시에만 버전을 올려 차트에서 이전 모델 기록(회색)과 구분합니다.
- DB 스키마는 기존 기록을 보존하며 하위 호환됩니다.
- 백업에 체크포인트가 포함되며, 복원 시 오프라인 시간은 회복으로 계산하지 않습니다.
