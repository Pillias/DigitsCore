# 코어 지수 계산 방식

이 문서는 현재 main의 `RollingScoreCalculator`를 기준으로 합니다. 코어 지수는 의료·심리 진단 점수가 아니라 사용 흐름을 비교하기 위한 제품 내부 지표입니다.

## 기본 원칙

- 계산 창은 **현재 시점까지 이어진 최근 24시간**입니다.
- 화면 ON·잠금 해제 상태에서 전면 또는 병렬 화면에 표시된 앱만 계산합니다.
- 화면을 끄고 쉬면 연속 사용 부하가 감소해 지수가 회복되며, 화면 OFF 백그라운드 재생은 사용시간에서 제외합니다.
- 좋은 앱 사용은 보너스가 아니라 더 작은 부하로 처리합니다.
- 모든 사용 부하가 0 이상이므로 서로 다른 등급의 사용이 가감으로 상쇄되지 않습니다.
- 최종 범위는 1~100입니다.

## 1. 최근 24시간 누적 부하

각 세션의 사용 분에 앱 등급별 계수를 곱합니다.

| 단계 | 이름 | 분당 부하 |
|---:|---|---:|
| 1 | 성장 | 0.040 |
| 2 | 균형 | 0.060 |
| 3 | 몰입 관리 | 0.120 |

몰입 관리 및 균형 앱의 심야 사용 구간에는 차등 배율을 적용합니다:
- **심야 1단계 (23:00~01:00)**: 취침 전 몰입 사용에 1.4~1.8배 적용
- **심야 2단계 (01:00~05:00)**: 수면을 방해하는 새벽 심야 사용에 2.0~2.8배 집중 적용

최근 24시간의 실제 `ACTION_USER_PRESENT`/`KEYGUARD_HIDDEN` 언락이 20회를 넘으면 초과 1회당 0.12 부하를 더합니다. 단순 화면 ON과 관측되지 않은 횟수의 추정치는 사용하지 않습니다.

분할 화면·PiP에서는 같은 1분을 앱마다 더하지 않습니다. 마지막 상호작용 앱이 화면시간을 소유하되, 점수 계산에는 동시에 표시된 앱 중 가장 높은 부하 등급 하나를 사용합니다. 예를 들어 성장 앱과 몰입 관리 앱을 10분 함께 표시하면 총 화면시간은 10분이고 점수 부하는 몰입 관리 10분입니다. 병렬 사용 자체의 추가 감점은 없습니다. 화면 OFF 백그라운드 재생은 제외합니다.

```text
rollingLoad = Σ(사용 분 × 등급별 분당 부하 × 심야 단계별 계수)
            + max(언락 수 - 목표치, 0) × 언락당 부하
```

## 2. 연속 사용 급성 부하와 회복

### 경계 처리와 기상 추정 (모델 4)

야간 미사용(21시 이후 또는 오전 11시 이전)은 시작부터 같은 제한식을 적용합니다. 150분 도달 시 이전 회복을 소급 취소하지 않습니다. 오전 5시 이후 시작한 휴식도 같은 제한을 받습니다. 이는 수면 측정값이 아닌 보수적인 야간 휴식 추정이며, 야간 근무 등 다른 생활 패턴에는 수면 회복 제한 설정을 끌 수 있습니다.

기상은 최소 휴식 후 오전 5~11시에 10분 이상 떨어진 두 번의 실제 잠금 해제, 또는 긴 야간 휴식 뒤 10분 이상 지속 사용으로 추정합니다. 정상 회복은 근거가 확보된 시점 이후에만 시작하며, 한 번의 짧은 확인에는 적용하지 않습니다. 휴식별 회복량은 한 번씩 계산한 뒤 누적하여 반복 계산 비용을 줄입니다.

4주 평균은 동일 점수 모델·프리셋의 일별 마지막 값만 사용합니다. 점선은 기준 변경일이며 평균선도 이 지점에서 끊습니다. 기록이 없는 날은 평균에서 제외합니다.

앱이 바뀌더라도 화면 사용 구간 사이의 간격이 5분 이하면 하나의 연속 흐름으로 봅니다. 분할 화면 포커스 전환이나 PiP 전환, 짧은 앱 전환으로 가속 시간이 초기화되지 않습니다. 블록의 연속 길이는 빈 간격을 제외한 실제 전면 사용시간이며, 블록 안에서 사용한 앱 등급별 시간 비율로 급성 계수를 계산합니다.

- 30분까지는 급성 부하가 없습니다.
- 30분을 넘긴 길이에 비선형 가속을 적용합니다 (1.3제곱).
- 등급별 급성 계수: 성장 0.10, 균형 0.45, 몰입 관리 1.00
- **일상 정상 휴식**: 사용을 멈추면 일상 균형은 90분, 집중 유지는 105분, 화면 휴식·가족 보호는 120분마다 급성 부하가 절반으로 감소합니다.
- **야간 휴식**: 기상 근거가 없는 21:00~11:00의 미사용은 시작부터 제한식을 적용합니다.
- **회복 제한**: 첫 120분은 회복으로 계산하지 않습니다. 이후 시간은 휴식 시작 시각이 늦을수록 60%→25%→8%→3%로 낮춰 환산합니다. 한 휴식 구간이 만드는 회복은 일상 균형 기준 최대 90분 환산으로 제한됩니다.
- **기상 후 회복**: 위의 반복 언락·지속 사용 근거가 확보된 뒤 화면을 내려놓은 시간부터 정상 휴식으로 계산합니다.
- 60분 이상 이어진 심야 몰입 관리 블록의 급성 부하 중 20~40%는 심야 사용 비율에 따라 회복 대상에서 분리해 최근 24시간 이월 부하로 유지합니다.

```text
weightedFactor = Σ(등급별 실제 사용시간 × 등급 계수) / 블록 실제 사용시간
peakAcute = 34 × (max(연속 사용 분 - 시작분, 0) / 150)^1.3 × weightedFactor
chronicCarryover = (60분 이상 심야 몰입) ? peakAcute × 심야 사용 비율 × 이월 비율 : 0
recoverableAcute = peakAcute - chronicCarryover
acuteLoad = 사용 중이면 recoverableAcute
            휴식 중이면 recoverableAcute × 0.5^(회복 환산 분 / 프리셋 회복 반감기)
totalLoad = 기본 최근 24시간 부하 + chronicCarryover + acuteLoad
```

화면을 끄고 쉬는 동안 회복 가능한 급성 부하가 감소하고 오래된 사용이 24시간 계산 범위를 벗어나면서 점수가 회복됩니다. 다만 밤 늦게 스마트폰을 몰아서 쓴 뒤 늦고 짧게 잔 경우에는 회복 환산 시간이 매우 작고 심야 이월 부하도 남으므로 아침에 점수가 급반등하지 않습니다. 반대로 앱이 실제 기상 잠금 해제를 관측한 뒤 사용자가 화면을 내려놓고 생활하면 그 시간부터 정상 회복됩니다.

설정 화면의 **「코어 지수 세부 계산 조정」**에서 연속 사용 가속 시작 시간, 심야 1·2단계 배율, 수면 중 회복 제한 여부, 수면 판정 미사용 시간, 일일 목표 언락 횟수를 사용자가 원하는 대로 직접 커스터마이징할 수 있습니다.

일상 균형에서 몰입 관리 앱을 연속 사용한 뒤 새로운 사용이 없다고 가정한 대표 시뮬레이션은 다음과 같습니다. 최근 24시간 누적 부하는 그대로 남고 연속 사용 급성 부하만 서서히 줄어듭니다.

| 사용 패턴 | 종료 직후 | 2시간 휴식 | 3시간 휴식 | 6시간 휴식 | 8시간 휴식 |
|---|---:|---:|---:|---:|---:|
| 3시간 연속 사용 | 42 | 56 | 62 | 72 | 74 |
| 5시간 연속 사용 | 22 | 37 | 43 | 52 | 53 |

심야 시뮬레이션은 단순 경과 시간이 아니라 취침 시각, 수면 중 실제 잠금 해제, 첫 아침 잠금 해제를 함께 입력해야 합니다. 같은 8시간 화면 미사용이라도 23시 취침과 03시 취침은 서로 다른 회복 환산값을 가지며, 기상 후 미사용 시간은 별도로 정상 회복됩니다.

## 3. 원점수

누적 부하와 급성 부하를 합쳐 포화 곡선으로 변환합니다.

```text
totalLoad = rollingLoad + acuteLoad
rawScore = 100 / (1 + (totalLoad / 45)^1.43)
```

이 곡선은 일반적인 사용을 60~90점대에 두고, 매우 높은 점수와 매우 낮은 점수가 쉽게 나오지 않도록 설계했습니다.

## 4. 50~90점 반응 확대

점수가 잘 변하지 않는 느낌을 줄이기 위해 50~90점에 단조 증가 S자 응답을 적용합니다. 50·70·90은 변하지 않으며 바깥 구간도 원점수를 그대로 사용합니다.

```text
x = (rawScore - 50) / 40
responsiveScore = 50 + 40 × [x + 0.8 × x × (1-x) × (2x-1)]
```

대표 변환은 다음과 같습니다.

| 원점수 | 표시 계산값 |
|---:|---:|
| 50 | 50 |
| 60 | 57 |
| 70 | 70 |
| 80 | 83 |
| 90 | 90 |

50 미만과 90 초과는 변환하지 않으므로 희소 구간의 성격은 유지됩니다.

## 5. 초기 보정

데이터가 없는 새 설치에서 극단 점수를 단정하지 않도록 80점에서 시작합니다. 누적 전면 사용 60분까지 실제 계산값의 비율을 선형으로 늘립니다.

```text
progress = min(누적 보정용 전면 사용 / 60분, 1)
score = 80 × (1-progress) + responsiveScore × progress
```

보정 중에도 점수는 표시되며 UI에서 보정 상태를 함께 안내합니다.

## 변화 설명과 회복 예상

현재 표본을 직전 표본과 비교해 연속 사용, 몰입 관리 앱, 잦은 언락, 회복, 보정 중 하나를 주원인으로 표시합니다. 회복 예상은 새로운 사용이 없다는 가정으로 5분 간격, 최대 3시간까지 같은 계산기를 다시 실행해 현재보다 3점 높은 지수에 처음 도달하는 시각을 찾습니다. 이는 보장값이 아니라 현재 기록에 근거한 조건부 예상입니다.

안내는 한 번에 한 가지 행동만 제안합니다. 별도의 1단계 알림은 프리셋별 관찰 구간(기본 30분)에서 코어 지수 하락, 화면 사용량 또는 연속 사용 조건을 만족할 때 무음·무진동으로 표시합니다. 사용자는 설정에서 모든 기준과 재알림 간격을 조정하거나 프리셋 기본값으로 복원할 수 있습니다.

| 프리셋 | 관찰 | 지수 하락 | 구간 내 화면 | 연속 사용 | 재알림 간격 |
|---|---:|---:|---:|---:|---:|
| 일상 균형 | 30분 | 5점 | 24분 | 35분 | 90분 |
| 집중 유지 | 30분 | 4점 | 20분 | 30분 | 60분 |
| 화면 휴식 | 30분 | 4점 | 22분 | 25분 | 60분 |
| 심야 균형 | 30분 | 4점 | 20분 | 30분 | 60분 |
| 가족 보호 | 30분 | 3점 | 18분 | 25분 | 45분 |

점수 하락은 관찰 시작 시각 이전의 가장 가까운 저장 표본과 현재 값을 비교합니다. 구간 내 화면 사용과 연속 사용은 실제 전면 사용 세션만 합산하며 화면이 꺼진 백그라운드 재생은 포함하지 않습니다.

## 저장과 통계

메인 화면, 앱 상세, 점수 상세, 상태바 알림과 위젯은 모두 현재 시각 직전 24시간의 앱별 사용·실행, 화면/관리 시간, 언락과 같은 코어 지수를 표시합니다. 자정 기준 집계는 날짜별 장기 통계를 만들기 위한 저장 단위이며 실시간 대시보드 값으로 사용하지 않습니다.

앱별 3단계 등급은 앱 사용이 만드는 부하를 구분하고, 목적형 프리셋은 전체 사용·연속 사용·심야 사용·언락의 민감도를 제한된 범위에서 조정합니다.

날짜별 사용시간과 언락은 기록이 있는 모든 날짜를 통계에 사용합니다. 4주 화면은 코어 지수의 기간 산술 평균을 별도 점수처럼 표시하지 않고, 현재 지수와 기간 내 최저·최고를 날짜별 추세로 보여줍니다.

화면이 켜진 동안 점수는 1분마다 계산하지만 DB에는 같은 5분 버킷의 최신 값만 갱신합니다. 이 표본은 30일 보관하며 통계에서 날짜를 선택하면 하루 중 코어 지수 변화를 표시합니다. 화면 OFF 동안에는 중간 표본을 만들지 않고, 다음 화면 ON 시 계산된 회복값으로 선을 이어 불필요한 백그라운드 실행을 피합니다.

## 코어 지수 프리셋

프리셋은 성장 앱에 점수를 더하는 방식이 아니라 최근 24시간 부하의 민감도를 바꿉니다. 앱별 3단계 등급은 그대로 적용됩니다.

| 프리셋 | 전체 사용 | 연속 사용 | 심야 | 언락 | 핵심 동작 |
|---|---|---|---|---|---|
| 일상 균형 | 표준 | 표준 | 표준 | 표준 | 일반적인 생활 패턴의 기본 기준 |
| 집중 유지 | 완화 | 강화 | 표준 | 강화 | 기본 화면 부하는 낮추고 앱 등급 추가 부하와 잦은 확인을 강화 |
| 화면 휴식 | 강화 | 강화 | 강화 | 완화 | 앱 종류와 관계없이 전체 화면시간과 긴 세션을 강조 |
| 심야 균형 | 표준 | 표준 | 강화 | 표준 | 00:00~05:00의 몰입 관리 앱 배수를 강화 |
| 가족 보호 | 강화 | 강화 | 강화 | 강화 | 전체 사용과 관리 앱, 긴 세션, 심야, 언락을 모두 엄격하게 반영 |

프리셋 변경은 최근 24시간 세션을 즉시 새 기준으로 다시 계산하므로 같은 사용 기록에서도 코어 지수가 달라질 수 있습니다. 일별 기록에 `coreIndexPresetId`를 저장하고 통계 그래프에서 변경일을 큰 포인트 테두리로 표시합니다. 기존 선택값은 `study`·`worker`→`focus`, `eye_health`→`screen_rest`, `kids`→`family`로 자동 이전합니다.

## 변경 시 검증 기준

- 빈 기록은 보정 상태 80점에서 시작해야 합니다.
- 3시간 연속 몰입 관리 앱은 약 40점대가 되어야 합니다.
- 3시간 연속 몰입 관리 사용 뒤 3시간 휴식은 60점대 초반, 6시간 휴식은 70점대 초반이어야 합니다.
