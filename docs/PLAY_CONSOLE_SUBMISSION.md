# Google Play 제출 준비서

이 문서는 현재 코드 기준의 초안입니다. Play Console의 실제 질문과 최종 바이너리를 기준으로 제출 직전에 다시 확인합니다.

## 업로드 키와 AAB

1. `scripts/create_upload_keystore.sh /안전한/오프라인/경로/digitscore-upload.jks`를 로컬에서 실행합니다.
2. keystore와 복구 정보를 암호화된 오프라인 장소 두 곳에 보관합니다. 저장소에는 커밋하지 않습니다.
3. `PLAY_RELEASE_CHECKLIST.md`의 네 개 GitHub Secret을 입력합니다.
4. 태그 빌드의 release AAB를 받은 뒤 `jarsigner -verify -verbose -certs DigitsCore-*.aab`로 서명을 확인합니다.
5. Play App Signing을 활성화하고 내부 테스트 트랙에 먼저 올립니다.

## 개인정보처리방침·지원 정보

- 앱 안의 개인정보 안내와 공개 HTTPS 정책의 내용·보유기간·삭제 경로를 일치시킵니다.
- `PRIVACY_POLICY.md`의 `[개발자명]`, `[지원 이메일]`, `[공개 정책 URL]`을 실제 값으로 바꿉니다.
- 공개 URL은 로그인 없이 열리고 수정 불가능한 일반 웹페이지여야 합니다.
- 스토어 지원 이메일은 실제로 수신·회신 가능한 전용 주소를 사용합니다.

## Data Safety 답안 초안

현재 manifest에는 `INTERNET` 권한이 없고 앱 서버, 광고 SDK, 분석 SDK가 없습니다. 사용 기록은 기기 내부 암호화 DB에서 처리됩니다. 따라서 현재 빌드에 한해 다음 방향을 검토할 수 있습니다.

- 개발자 또는 제3자 서버로 자동 수집: 없음
- 제3자 공유: 없음
- 전송 중 암호화: 서버 전송 자체가 없음
- 삭제 요청: 앱 설정의 `모든 사용 기록 즉시 삭제`, Android 앱 데이터 삭제, 앱 제거
- 계정 생성: 없음
- 사용자 시작 공유: 암호화 백업과 버그 리포트는 Android Sharesheet에서 사용자가 대상과 내용을 직접 선택함

최종 답변은 Google Play의 `수집` 정의, 사용자 시작 전송 예외, 실제 포함 SDK를 Play Console에서 다시 대조해야 합니다. 기능·SDK·권한을 추가하면 이 답안과 정책을 같은 변경에서 갱신합니다.

## Foreground Service `specialUse` 제출 문구 초안

**기능:** 사용자가 앱 안에서 추적을 명시적으로 켠 동안, 화면이 켜지고 잠금 해제된 상태의 최상단 앱 전환과 실제 잠금 해제 이벤트를 지속 관측하여 최근 24시간 코어 지수와 상태바 알림/위젯을 갱신합니다. 네트워크 전송은 하지 않습니다.

**지연 영향:** 작업이 지연되면 앱 전환 사이의 짧은 사용과 잠금 해제 이벤트가 소급 복원되지 않을 수 있어 사용자에게 표시되는 앱별 시간과 지수가 부정확해집니다.

**중단 영향:** 서비스가 중단된 구간은 ‘미기록’으로 남고 추정값으로 채우지 않습니다. 사용자는 지속 알림과 설정에서 언제든 추적을 중지할 수 있습니다.

**사용자 인지:** 추적은 온보딩/설정에서 사용자가 켜며, 실행 중에는 지속 알림이 표시됩니다. 알림과 앱 설정에서 즉시 중지할 수 있습니다.

### 시연 영상 촬영 순서

1. 새 설치 상태에서 추적 OFF와 기기 내 처리 고지를 보여줌
2. 사용 정보 접근 화면으로 이동해 사용자가 직접 허용
3. 추적 ON 후 지속 알림과 코어 지수 표시
4. 다른 앱을 전면에서 짧게 사용하고 DigitsCore 앱별 시간/실행 횟수 갱신 확인
5. 화면을 끈 동안 시간이 늘지 않는 장면
6. 알림의 중지 또는 설정의 추적 OFF로 서비스가 종료되는 장면

영상은 전체 흐름을 읽을 수 있는 해상도로 촬영하고 공개 또는 심사자가 로그인 없이 접근 가능한 URL로 제공합니다.

## Android Vitals 운영

- 내부 테스트부터 Crash, ANR, excessive partial wake lock, 과도한 백그라운드/배터리 지표를 매일 확인합니다.
- 이메일 경고를 활성화하고 매 릴리스 전 최근 28일과 새 버전만 필터링한 화면을 보관합니다.
- user-perceived crash/ANR 신규 회귀, wake lock 경고 또는 제조사 한정 급증이 생기면 단계적 배포를 중단합니다.
- 버그 리포트의 앱 버전·기기·CPU/조회 비용을 Vitals 클러스터와 함께 비교합니다.

Google은 Android Vitals를 앱의 기술 품질과 Play 노출 판단에 사용하므로 수치가 없는 상태를 출시 완료로 간주하지 않습니다.

## 접근성·화면 매트릭스

각 조합에서 온보딩 → 대시보드 → 통계 → 앱 상세 → 설정 → 버그 리포트까지 확인합니다.

| 조합 | 확인 사항 |
|---|---|
| 글꼴 100/150/200% | 잘림, 겹침, 버튼 접근, 그래프 설명 |
| 밝은/어두운 테마 | 텍스트·그래프·상태색 대비 |
| TalkBack | 읽기 순서, 역할/상태, 아이콘 설명, 터치 대상 |
| 세로/가로 | 스크롤 가능, 차트 크기, 다이얼로그 범위 |
| 휴대전화/7~8인치/10인치+ | 최대 폭, 빈 공간, 2열 전환, 위젯 크기 |
| 한국어/영어 | 한글 잔존, 길어진 영문 잘림, 위젯/알림 언어 |

접근성 자동 검사는 보조 수단이며 TalkBack 수동 탐색과 실제 큰 글꼴 검사를 대체하지 않습니다.
