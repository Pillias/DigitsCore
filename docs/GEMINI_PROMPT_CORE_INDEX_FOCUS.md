# 작업 지시: 코어 지수 집중 UX + 잠금 해제 점수 반영 (v0.9.36 한 번에 반영)

아래 전체를 Gemini에게 붙여 넣으세요.

---

## 배경

DigitsCore의 핵심은 **선택지를 줄이기 위해 하나의 숫자(코어 지수)로 모은 것**이다. 이번 작업은 새 기능이나 선택지를 더하지 않고, 이미 있는 숫자를 **지수의 언어(±P)로 바꿔 말하는 것**이다. 첫 화면은 위에서 아래로 "지금 지수 → 평소와 비교 → 할 일 하나 → 왜(±P)" 순서로 읽혀야 한다.

먼저 읽을 문서 (이 지시서와 다르면 이 지시서가 우선):

- `docs/CORE_INDEX_UX_BENCHMARK.md` — 벤치마킹 결론, 잠금 해제 점수 규칙, 끝의 [Claude 재검토]
- `docs/V0_9_35_REVIEW_AND_ROADMAP.md` — 끝의 통합 로드맵
- `DEBATE.md` 안건 18 — 잠금 해제 간격 기반 점수 반영
- `docs/GLOSSARY.md`, `docs/DESIGN_SYSTEM.md`, `docs/SCORING.md`

작업 브랜치: `feature/screen-time-parity`(마지막 커밋 `2946c20`)에서 `feature/core-index-focus`를 만들어 작업한다. **Phase 1·2·3을 한 번에 반영해 v0.9.36 하나로 출시한다.** 항목마다 커밋하고(문제 항목만 되돌릴 수 있게), 고친 로직에는 테스트를 붙인다.

**순서와 관문**: 1 → 2 → 3 순서로 진행한다(Phase 3은 2-2의 분해를 쓰고, 1-3의 회복 계산은 2-1 뒤에 다시 맞춘다). 각 Phase가 끝날 때마다 `./gradlew :app:testDebugUnitTest`와 `STRICT=1 bash scripts/design_check.sh`를 돌려 통과해야 다음 Phase로 넘어간다.

## 절대 규칙

1. **선택지를 늘리지 않는다.** 새 설정 항목, 새 버튼, 새 토글, 새 알림 채널을 만들지 않는다. 사용자가 고를 것이 늘어나면 그 항목은 구현하지 말고 보고한다.
2. **새 점수·색·개념을 만들지 않는다.** 점수는 코어 지수 하나, 색은 지수 4단계(80/60/40)만 쓴다. 배지·보석·리더보드·다른 사용자 비교는 만들지 않는다.
3. **코어 지수 계산은 Phase 2의 2-1(안건 18)에서만 바꾼다.** 그 밖의 항목에서는 `engine/CumulativeScoreEngine.kt`, `engine/CumulativeTimeline.kt`, `engine/RestPhasePolicy.kt`, `data/CumulativeScoreStore.kt`의 계산과 체크포인트 형식을 건드리지 않는다. 표시용 분해는 기존 `onMovement` 콜백처럼 **읽기만** 하는 방식으로 한다.
4. **앱을 막지 않고, 인터넷으로 보내지 않고, 새 `uses-permission`을 추가하지 않는다.**
5. **기존 사용자 데이터를 잃지 않는다.** 이번 작업은 Room 스키마 변경 없이 하는 것이 목표다. 꼭 필요하면 `MIGRATION_20_21`을 만들고 0.9.32·0.9.35 → 새 버전 업데이트 테스트를 한다. `fallbackToDestructiveMigration` 금지.
6. **용어·디자인 기준**: 시간 `min`, 횟수 `x`(문장 속은 "회"/"times"), 지수 `P`. 글자 크기 `DigitsTextSize`, 모서리 `DigitsShape`, 점수 색 `Score*`/`Score*Text`만 쓴다. `Icons.Rounded.*`만, 굵기는 Normal·Medium·Bold만. 새 문구는 `values/strings.xml`과 `values-en/strings.xml`에 함께 넣는다. 느낌표·이모지·기호 글자 금지.
7. **순수 로직은 분리한다.** 계산(분해, 비교, 잠금 해제 Δ, 문구 재료)은 Android 의존성 없는 `object`/함수로 `engine/` 또는 `model/`에 두고 `app/src/test`에 JUnit 테스트를 붙인다.
8. **버전·비밀**: 릴리스 빌드를 만들지 않는다. `keystore/`, `local.properties`를 건드리지 않는다.
9. **DEBATE 규칙**: 안건 18의 최종 합의안이 기록되기 전에는 2-1을 구현하지 않는다(아래 2-0 참고).

## 꼭 알아야 할 현재 구조

- 지수 엔진은 `CumulativeScoreEngine.advance()`의 1분 단위 루프다. 활동 종류는 `NORMAL_USE`, `MANAGED_USE`, `EXEMPT_*`, `AWAKE_REST`, `SLEEP`, `UNKNOWN`이다. 화면 꺼짐 휴식 3시간(`awakeRestCapMinutes`) 이후는 수면 회복 속도로 바뀐다.
- **지금은 잠금 해제가 점수에 들어가지 않는다.** `openingLoss = 0.0`이고, `CumulativeTimeline`의 `openings`는 앱 실행 단위다. 그런데 `CoreIndexCoach`는 `FREQUENT_UNLOCKS → BATCH_PHONE_CHECKS`를 안내한다. 이 모순은 2-1로 풀린다.
- `CumulativeTimeline.advance(... onMovement: (ScoreMovement) -> Unit)`가 구간별 `before/after/packageName`을 이미 내보낸다. 분해(2-2)는 이것을 쓴다.
- 저장 번호: `ScoreModel.CURRENT_STORED = 5`(계산 설정 v2). 통계는 `scoreModelVersion`으로 이전 모델 구간을 회색으로 구분한다.
- 지수 표본: `core_index_samples`(5분 단위, 최근 30일, 화면 켜진 동안만).
- 잠금 해제 이벤트: `device_interaction_events`(실제 `ACTION_USER_PRESENT`/`KEYGUARD_HIDDEN`, 보관 최근 48시간). 화면 꺼짐은 `ForegroundTimelineEventType.SCREEN_NON_INTERACTIVE`/`KEYGUARD_SHOWN`.
- 단계 표시: `engine` 패키지의 `ScoreGrade`(S~F, 90/80/70/55/40)를 `DashboardScreen.kt`, `widget/ScoreWidget.kt`, `notification/ScoreNotificationManager.kt`, `i18n/ScoreText.kt`가 쓴다. 색 구간(80/60/40)과 경계가 달라 75P는 노랑인데 B, 58P는 주황인데 C로 보인다.

**2-1. 잠금 해제 간격 기반 점수 (안건 18 합의 후에만)**
- 잠금 해제 1회마다 **직전에 화면이 꺼져 있던 시간 g**로 판정한다. g는 엔진이 `AWAKE_REST`로 분류한 분만 센다. `SLEEP` 분이 끼면 그 잠금 해제는 뉴트럴이다. 기준은 `T0 = 12min`이다.

  | g | Δ |
  | --- | --- |
  | < 10s | 계산 안 함 |
  | 10s ~ T0 | `−0.05 × (1 − g/T0) × speedDown()` |
  | T0 ~ 2·T0 | `+0.02 × ((g − T0)/T0) × speedUp()` |
  | ≥ 2·T0 | `+0.02 × speedUp()` (상한) |

- **뉴트럴**: 화면이 켜진 시간(잠금 해제 기회 없음), 수면 뒤 첫 잠금 해제, 잠금 해제 직후 첫 앱이 `EXEMPT_UNLIMITED`(통화·내비)인 경우, 잠금 해제 없이 화면만 켠 경우.
- **하루 상한**: 논리적 하루(05:00) 기준 감점 합계 −3P, 가점 합계 +1P.
- **구현**:
  - `CumulativeScoreConfig`에 `unlockReferenceMinutes = 12.0`, `unlockMaxLoss = 0.05`, `unlockMaxGain = 0.02`, `unlockDailyLossCap = 3.0`, `unlockDailyGainCap = 1.0`을 추가한다.
  - `version`을 2 → 3으로 올리고, `ScoreModel.CURRENT_STORED`를 5 → 6으로 맞춘다.
  - Δ 계산은 순수 함수(`UnlockPacingPolicy` 등)로 분리한다.
  - `CumulativeTimeline`이 잠금 해제 시각에 Δ를 적용하고, `ScoreMovement`에 잠금 해제 구간임을 표시한다(예: `kind = UNLOCK`).
- **과거 기록은 재계산하지 않는다.** 통계에서 이전 모델 구간이 회색으로 구분되는지 확인한다.
- **잠금 해제 이벤트 보관(48시간)보다 긴 구간을 다시 계산할 때**(`CoreIndexHistoryRepair` 등)는 잠금 해제 Δ를 0으로 둔다. 보관 기간을 늘리지 않는다.
- `CoreIndexCoach`의 `FREQUENT_UNLOCKS`는 실제 잠금 해제 Δ 합계(최근 1시간 −0.3P 이하 등)로 판단하게 바꾼다. 새 문구: "12min 넘게 내려놓으면 잠금 해제가 +P로 바뀌어요".
- **테스트** (`docs/CORE_INDEX_UX_BENCHMARK.md`의 상황표, 75P 기준):

  | 상황 | 기대값 |
  | --- | --- |
  | 하루 100회, 12분 간격 | 0P |
  | 화면 켜진 60분 | 0P |
  | 1시간 20회 (3분 간격) | −0.75P ± 0.02 |
  | 10분 동안 10회 | −0.46P ± 0.02 |
  | 하루 150회, 8분 간격 | −2.5P ± 0.1 |
  | 하루 200회 이상 | −3P (상한) |
  | 2시간 쉬고 켬 | 잠금 해제 몫 +0.02P |
  | 수면 뒤 첫 잠금 해제 | 0 |
  | 10초 미만 | 무시 |
  | 통화 앱 첫 실행 | 0 |

  기존 엔진 테스트는 v2 설정으로 그대로 통과해야 한다.
- `docs/SCORING.md`에 v3 규칙을 추가한다.

**2-2. 지수 변화 분해 (±P)**
- 순수 함수로 최근 24시간 구간을 다시 계산하면서 `ScoreMovement`를 범주별로 더한다. 범주는 관리 앱 / 그 외 앱(일반 + 면제 한도를 넘은 필수·공부) / 잠금 해제 / 쉼(`AWAKE_REST` + `SLEEP`)이다.
- 비례 배분은 쓰지 않는다. 범주 합 = 지금 지수 − 24시간 전 지수(정확값 기준)여야 한다. 1/99P 경계에서 잘린 양만 오차로 허용한다.
- 앱별 Δ도 같은 계산에서 `packageName`으로 모은다.
- 대시보드를 열 때마다 30일을 재계산하지 않는다. 서비스가 이미 하는 정산 주기에 결과를 메모리/prefs에 캐시한다.
- 테스트: 범주 합이 지수 변화와 0.05P 이내로 같다. 감점과 회복이 비슷해 순변화가 0에 가까워도 각 범주 값이 정상으로 나온다.

**2-3. 대시보드 요약 3칸과 앱 행을 ±P로**
- 요약 3칸의 큰 글자를 `앱 사용 −6P` · `잠금 해제 −1P` · `쉼 +4P`로 바꾼다. 바로 아래 작은 보조 글자(`DigitsTextSize.caption`, 보조 색)로 원값 `65min` · `48x` · `192min`을 함께 적는다.
- 앱 사용 칸을 누르면 관리 앱 / 그 외 앱의 ±P와 원값이 보인다. 기존 상세 화면을 재사용하고 새 화면은 만들지 않는다.
- 앱 행 오른쪽에 그 앱의 −P를 함께 적고, 정렬은 영향 큰 순서로 바꾼다(원값 정렬은 상세에서).
- 기록이 부족해 계산이 안 되면 지금처럼 원값만 보여 준다.

**2-4. 평소와 비교, 방어선 여유**
- 지수 옆 한 줄에 "평소 이 시간보다 +5P"를 쓴다. 기준은 `core_index_samples`의 최근 14일 같은 시각(±30분) 지수 중간값이고, 표본이 있는 날이 7일 미만이면 숨긴다. 새 저장 테이블은 만들지 않는다.
- 상태바 상시 알림의 둘째 줄을 오늘의 지수 방어선까지 남은 여유로 바꾼다: "방어선까지 여유 4P", 미만이면 "방어선까지 3P". 새 알림을 만들지 않는다.

**2-5. 차트 기준선**
- `StatisticsExplorer.kt` 1008행의 75P 고정 점선을 **오늘 정한 지수 방어선**으로 바꾼다(목표가 없으면 75P).
- 4주 일별 차트에도 같은 점선을 추가한다.
- 선택된 날짜·시간대가 있을 때 비선택 구간의 투명도를 0.35로 낮춘다.

**2-6. 2×2 위젯 축소**
- 2×2는 지수 숫자 + 링 + 단계 이름만 남기고, 목표는 상태 점 3개로 줄인다.
- 4칸 이상 위젯은 지금 구성을 유지한다.
- 글자 9sp 이상, 130% 글자에서 넘침 없음.

## Phase 3

**3-1. 쉬는 동안 오른 P 안내**
- 화면 꺼짐 휴식으로 +2P 이상(또는 10min 이상) 올랐으면, 화면을 켠 뒤 대시보드 첫 진입에 한 번만 2-4의 비교 줄 자리에 "쉬는 동안 +nP"를 보여 준다.
- 알림·토스트는 쓰지 않는다.

**3-2. 하루 그래프에 원인 표시**
- 통계 하루(5분 단위) 그래프에서 가장 크게 떨어진 구간 최대 2곳(원인 앱 이름)과 가장 크게 오른 구간 1곳("화면 꺼짐")만 표시한다. 하루 최대 3개다.
- 130% 글자에서 겹치지 않게 배치하고, 겹치면 작은 쪽을 뺀다. 데이터는 2-2의 분해를 쓴다.

**3-3. 주간 리포트를 지수 중심으로**
- 첫 줄은 지난주 평균 지수 + 직전 4주 평균 대비 위·아래 화살표 하나다(직전 기록 없으면 화살표 숨김).
- 나머지(앱 사용·잠금 해제·쉼, 앱 변화, 한도 선택)는 "지수를 움직인 이유" 한 카드로 묶고, P 단위로 쓴다.
- 버튼은 닫기와 "상세 통계 보기" 두 개다. 상세 통계는 **지난주(월~일) 범위가 선택된 상태**로 연다.
- 목표 설정 버튼 같은 다른 액션은 넣지 않는다.
