# DigitsCore 코어 지수 집중 UX 벤치마킹

2026-10-26 · 박진우

## 요약

하나의 점수로 행동을 바꾸는 앱들은 공통적으로 **점수 하나를 크게 → 그 점수를 움직인 이유 → 지금 할 한 가지 → 나의 평소와 비교** 순서로 보여 줍니다. DigitsCore는 지수와 코치 문구를 이미 갖고 있지만, 대시보드의 나머지 숫자(시간·횟수)가 지수와 따로 놓여 시선이 분산됩니다. 새 기능이나 선택지를 더하지 않고, **이미 있는 숫자를 지수의 언어(P)로 바꿔 말하는 것**이 핵심 제안입니다.

우선 반영할 5가지:

1. **지수 옆에 단계 이름**: 숫자와 색에 한 단어를 붙입니다 (Oura의 Optimal·Good·Fair·Pay attention 방식).
2. **요약 3칸을 '지수에 준 영향'으로**: 분·회 대신 "앱 사용 −6P", "잠금 해제 −1P", "쉼 +4P"처럼 P로 표시합니다. 잠금 해제도 새 규칙으로 지수에 들어갑니다 (Oura 기여 요소, Credit Karma 영향도 방식).
3. **할 일은 항상 하나**: 지수 바로 아래에 "10분 쉬면 +3P" 같은 행동 하나만 둡니다 (WHOOP 목표 강도, Apple 코칭 방식).
4. **평소의 나와 비교**: "평소 이 시간보다 +5P", 주간은 "지난 4주 평균보다 −2P"처럼 화살표 하나로 보여 줍니다 (Oura 기준선, Apple 추세 방식).
5. **하루 그래프에 오르내린 이유 표시**: 지수가 크게 떨어지거나 오른 구간에 원인을 붙입니다 (Garmin Body Battery의 충전·소모 타임라인 방식).

다른 사람과의 비교, 배지 수집, 점수 추가는 하지 않습니다.

## 비교 기준

기능 목록이 아니라 **점수를 보여 주는 방식**만 비교했습니다. 그래서 스크린 타임 앱보다 건강·금융처럼 하나의 점수로 매일 행동을 바꾸는 앱을 주로 봤습니다.

- **집중**: 화면을 열었을 때 점수 말고 다른 숫자가 시선을 빼앗지 않는가, 다른 숫자는 점수의 이유로 보이는가
- **격려**: 점수를 올리려면 지금 무엇을 하면 되는지, 그 결과가 얼마인지 한 문장으로 말하는가
- **비교**: 점수가 좋은지 나쁜지를 무엇과 견주어 보여 주는가 (어제, 평소, 목표, 다른 사람)

각 제안은 앞서 정한 원칙을 통과해야 합니다: 사용자가 고를 것이 늘지 않고, 코어 지수 말고 다른 점수·색·개념이 생기지 않아야 합니다.

## 벤치마킹 대상별 보여 주는 방식

Opal을 뺀 다섯 앱 모두 점수는 하나, 점수 아래는 그 이유, 그다음은 할 일 하나입니다. 다른 사람과 비교하는 앱은 Opal 하나뿐입니다.

| 앱 | 점수 | 집중: 점수 아래에 무엇을 두나 | 격려: 행동 유도 | 비교 대상 |
| --- | --- | --- | --- | --- |
| [Oura 준비도](https://support.ouraring.com/hc/en-us/articles/360025589793) | 0~100, 4단계 이름(Optimal·Good·Fair·Pay attention) | 기여 요소(심박·체온·수면·활동 균형 등) | 70 미만이면 회복 우선 안내, 85 이상이면 왕관 표시 | 나의 최근 14일 vs 최근 2개월 |
| [WHOOP 회복](https://www.whoop.com/au/en/thelocker/how-does-whoop-recovery-work-101/) | 1~99%, 녹·노·빨 3구간 | HRV·안정 심박·수면 | 회복에 맞춘 오늘의 목표 강도 하나 | 구간 색 |
| [Garmin Body Battery](https://www.wareable.com/garmin/garmin-body-battery-explained-how-it-works-8734) | 1~100 | 충전(+)·소모(−) 숫자, 하루 타임라인 | 수면·휴식으로 충전 | 하루·주·월 추세 |
| [Apple 활동 링](https://apple.com/uk/watch/close-your-rings) | 링 3개(목표 대비 달성률) | "매일 링 닫기" 하나의 목표 | 하루 끝 마무리 알림, 기록·연속 어워드 | [최근 90일 vs 365일 화살표, 하락 시 코칭 문구](https://support.apple.com/guide/watch/track-daily-activity-apd3bf6d85a6/watchos) |

| [Opal](https://apps.apple.com/TW/app/id1497465230) | 포커스 점수 | 집중·방해 시간 | 보석 보상, 친구 리더보드 | 다른 사용자 |

DigitsCore와 가장 가까운 것은 Garmin Body Battery입니다. 쓰면 줄고 쉬면 차는 연속된 점수라는 구조가 코어 지수의 휴식 회복 모델과 같습니다.

## 1. 인덱스에 집중시키는 화면 구성

지금 대시보드는 지수 아래에 화면 시간·잠금 해제·관리 앱 시간이 **분과 회로** 따로 놓여 있어, 사용자가 숫자 네 개를 따로 해석해야 합니다. 비교 대상들은 점수 아래의 숫자를 모두 **점수의 이유**로 보여 줍니다.

| 비교 대상의 방식 | DigitsCore 지금 | 제안 |
| --- | --- | --- |
| Oura·WHOOP: 숫자 + 단계 이름 하나 | 숫자, 4색 구간(80/60/40), 그리고 별도의 S~F 6등급(90/80/70/55/40)이 함께 있음. 예) 58P는 주황인데 C(주의), 75P는 노랑인데 B(양호) | **단계는 4색 하나로 통일**하고 각 단계에 이름 한 단어를 붙입니다. S~F 등급은 화면에서 내립니다. 기준이 두 개면 사용자가 어느 쪽을 믿어야 할지 모릅니다. |
| Oura 기여 요소, Credit Karma 영향도 | 요약 3칸이 분·회 원값 | 같은 3칸을 **지수에 준 영향(P)** 으로 바꿉니다: 큰 글자는 실제 사용량(앱 사용 65min · 잠금 해제 48x · 쉼 1180min), 바로 아래 줄에 그만큼의 효과("지수 −6P" · "지수 −1P" · "지수 +4P")를 둡니다. P만 보여 주면 무엇 때문인지 바로 읽히지 않아 사용량을 앞에 둡니다(사용자 결정, 2026-10-27). 잠금 해제는 아래 '잠금 해제 점수 규칙'으로 ±P가 됩니다. |
| WHOOP: 점수 바로 밑에 오늘 할 것 하나 | 코치 문구(`CoreIndexCoach`)가 있음 | 지수 바로 아래 한 줄로 고정: 원인 한 줄 + 행동 한 줄. 버튼은 두지 않습니다. |
| Garmin: 위젯·알림도 같은 숫자 하나 | 위젯·상태바·런처가 같은 지수를 씀 | 지금 방식 유지. 위젯 2×2는 지수 숫자와 링만. |
| 앱 목록은 원인 설명용 | 앱별 행이 분 단위 | 앱 행 오른쪽에 그 앱이 지수에 준 영향(−P)을 함께, 정렬도 영향 큰 순서로. |

완성된 첫 화면은 위에서 아래로 "지금 지수 → 평소와 비교 → 할 일 하나 → 왜(P)" 순서로 읽힙니다.

**그림: 대시보드 위쪽 · 지금과 제안** (값과 단계 이름은 예시)

| 영역 | 지금 | 제안 |
| --- | --- | --- |
| 지수 | **75** · 노랑 구간 · B (양호) · "좋은 흐름입니다." (색과 등급 기준이 다름) | **75** · 보통 (노랑) · 평소 이 시간보다 +5P · 방어선까지 여유 4P |
| 둘째 줄 | 관리 대상 앱을 조금만 줄여보세요 | **화면 끄고 15분 쉬면 78P** |
| 요약 3칸 | 화면 시간 3시간 12분 · 잠금 해제 48회 · 관리 앱 1시간 5분 | 앱 사용 192min(지수 −6P) · 잠금 해제 48x(지수 −1P) · 쉼 1248min(지수 +4P) |
| 오늘의 목표 | 3칸 | 3칸 (보조, 작게) |
| 앱 행 | 유튜브 48분 · 카카오톡 35분 | 유튜브 · 48분 −4P · 카카오톡 · 35분 −1P |

오른쪽은 새 칸이나 버튼 없이 같은 자리의 내용만 바꾼 것입니다. 단계 이름(안정·보통·주의·휴식 필요 등)은 용어집에서 정합니다.

## 2. 인덱스를 높이도록 격려하는 방식

비교 대상 앱들은 격려할 때 **행동 하나와 그 결과를 같은 단위로** 말합니다. WHOOP은 회복 점수로 오늘의 목표 강도를, Apple은 "하루 400m 더 걷기" 같은 구체적 행동을 줍니다. DigitsCore의 단위는 P입니다.

| 비교 대상의 방식 | DigitsCore 지금 | 제안 |
| --- | --- | --- |
| WHOOP 목표 강도, Apple 코칭: 행동 + 결과 | `CoreIndexCoach`가 회복 목표(지금 +3P)와 필요한 분을 이미 계산 | 문구를 항상 "[행동] → [+nP]" 한 형식으로: "화면 끄고 15분 쉬면 78P". 단계 경계가 가까우면 그 경계를 목표로: "20분 쉬면 초록(80P)". |
| Oura 왕관(85 이상), Apple 링 닫기 | 지수 방어선 목표, 스탬프·패스 보상이 있음 | 새 배지 없이 기존 방어선을 '오늘의 링'처럼: 지수 링 위에 방어선 위치를 표시하고 하루 끝에 지켰으면 스탬프가 찍히는 한 가지 보상만. |
| Apple 하루 끝 알림 | 아침 브리핑, 주간 리포트가 있음 | 새 알림을 더하지 않고 상태바 상시 알림의 둘째 줄을 "방어선까지 4P 여유"처럼 남은 여유로. |
| Garmin: 충전 요인을 칭찬하듯 보여 줌 | 화면 꺼짐 회복이 점수에 반영되지만 말해 주지 않음 | 화면을 다시 켰을 때 오른 만큼을 알려 줍니다: "쉬는 동안 +6P". 긍정적 피드백이 내려갈 때의 경고보다 더 자주 보이게. |
| Apple 연속 기록 | 스탬프 누적 | "방어선 n일 연속" 숫자 하나만. 끊겨도 벌점 없음. |

| 잠금 해제 (새 규칙) | 잠금 해제 수는 목표 3에서 횟수로만 보임 | 화면을 12분 넘게 꺼 두면 다음 잠금 해제가 +P가 됩니다. 문구: "12분 넘게 내려놓으면 잠금 해제가 +P로 바뀌어요". |

원칙: 격려는 항상 지수로 말합니다. "유튜브 30분 줄이기"가 아니라 "관리 앱을 30분 덜 쓰면 +5P"입니다.

## 3. 비교해서 보여 줄 것

점수는 비교할 기준이 있어야 의미가 생깁니다. 비교 대상 앱들은 대부분 **다른 사람이 아니라 평소의 나**와 비교합니다. Oura는 최근 14일을 최근 2개월과, Apple은 최근 90일을 365일과 비교하고 내려갈 때만 코칭합니다.

| 비교 | 어디에 | 보여 주는 방식 | 참고 |
| --- | --- | --- | --- |
| 지금 vs 평소 이 시간 | 대시보드 지수 옆 | "평소 이 시간보다 +5P" 한 줄. 최근 14일 같은 시각 지수의 중간값 기준 | Oura 기준선. 어제 하루와 비교하면 흔들림이 커서 평소가 낫습니다. |
| 지금 vs 방어선 | 지수 링, 상태바 | 링 위 방어선 표시, "여유 4P" | Apple 링. 목표 대비 남은 거리만. |
| 이번 주 vs 평소 | 주간 리포트 첫 줄, 통계 | 지난주 평균 지수와 직전 4주 평균의 차이, 위·아래 화살표 하나 | Apple 추세. 내려갔을 때만 가장 크게 깎은 원인 하나를 같이. |
| 원인의 변화 | 주간 리포트, 앱 상세 | "유튜브가 지수를 지난주보다 3P 더 깎음". 분 단위 증감 대신 P 단위 | Credit Karma 영향도 |
| 하루의 오르내림 | 통계 하루 그래프 | 크게 떨어진 구간에 원인 앱, 크게 오른 구간에 "화면 꺼짐" | Garmin 타임라인 |

다른 사용자와의 비교(Opal 방식)는 하지 않습니다. 서버가 필요하고, 점수를 내 행동이 아닌 순위로 읽게 됩니다.

## 잠금 해제 점수 규칙 (사용자 결정, 2026-10-26)

잠금 해제도 지수에 넣습니다. 횟수를 직접 세지 않고 **직전에 화면을 얼마나 오래 꺼 두었나**로 판정합니다. 기준은 12분(시간당 5회, 하루 약 100회)입니다. 12분보다 빨리 켜면 감점, 늦게 켜면 미세 가점입니다. 화면이 켜져 있는 동안은 잠금 해제가 일어날 수 없으므로 자연히 0입니다.

| 직전에 화면을 꺼 둔 시간 | 잠금 해제 1회의 점수 |
| --- | --- |
| 10초 미만 | 계산 안 함 (자동 꺼짐 후 바로 켬) |
| 10초 ~ 12분 | 감점: 최대 −0.05P, 12분에 가까울수록 0 |
| 12분 ~ 24분 | 가점: 0 → +0.02P |
| 24분 이상 | +0.02P (상한, 그 이상은 휴식 회복이 맡음) |

- 다른 항목처럼 지수가 높을수록 감점이 조금 세지고(`speedDown`), 낮을수록 회복이 빨라집니다(`speedUp`).
- 하루(05:00 기준) 합계는 감점 −3P, 가점 +1P에서 멈춥니다.
- **뉴트럴**: 화면이 켜진 시간(게임·영상), 잠든 뒤 아침 첫 잠금 해제, 통화·내비게이션으로 연 잠금 해제, 잠금 화면에서 알림만 본 경우.
- 오래 내려놓은 것은 이미 휴식 회복으로 보상됩니다. 2시간 쉬고 켜면 휴식 약 +1.1P에 잠금 해제 +0.02P입니다. 같은 행동을 두 번 보상하지 않으려고 가점을 24분에서 멈춥니다.

| 상황 (75P 기준) | 영향 |
| --- | --- |
| 하루 100회, 고르게 | 0P |
| 게임 1시간 | 0P |
| 1시간에 20회 (3분 간격) | −0.75P |
| 10분 동안 10회 연속 확인 | −0.46P |
| 하루 150회, 고르게 | −2.5P |
| 하루 200회 이상 | −3P (하루 상한) |
| 시간당 2회 × 8시간 | +0.3P |
| 2시간 안 보다가 켬 | +0.02P (+ 휴식 약 +1.1P) |

비교: 관리 앱 1시간 약 −2.5P, 화면 꺼짐 휴식 1시간 약 +0.6P. 점수 의미가 바뀌므로 DEBATE 안건 18로 올렸고, 점수 계산 설정을 v2 → v3(저장 번호 5 → 6)으로 올립니다.

## 하지 않을 것

비교 대상에 있지만 코어 지수 하나라는 컨셉을 흐리는 것들입니다.

- **점수 여러 개**: Oura는 준비도·수면·활동, WHOOP은 회복·수면·강도를 따로 보여 줍니다. DigitsCore는 하나만 둡니다. 같은 이유로 S~F 등급도 내립니다.
- **링·목표 여러 개를 같은 무게로**: Apple은 링 3개가 동등합니다. DigitsCore의 오늘의 목표 3개는 지수 아래 보조로 두고, 지수보다 크게 보이지 않게 합니다.
- **보석·배지 수집, 리더보드**(Opal): 모으는 것이 지수 올리기보다 우선됩니다.
- **새 색**: 색은 4단계만 뜻합니다. 시간대별 색, 앱 분류별 색을 지수 색과 같은 자리에 쓰지 않습니다.
- **원값을 주인공으로**: 분·회는 상세 화면에서만 주인공입니다. 첫 화면과 알림에서는 P로 말합니다.
- **행동 버튼 여러 개**: 할 일은 한 줄 문장 하나이고, 사용자가 고를 버튼은 없습니다.

| 요약 3칸에 `잠금 해제(−P)` (안 A·안 B 모두) | 지금 지수 엔진은 잠금 해제를 감점하지 않습니다. `openingLoss = 0.0`이고 다른 경로도 없습니다. 지수를 움직이는 것은 관리 앱 사용, 그 외 앱 사용(일반 + 면제 한도를 넘은 필수·공부 앱), 화면 꺼짐 휴식·수면 세 가지뿐입니다. | (사용자 결정 후 변경) 잠금 해제도 새 규칙으로 지수에 넣기로 함 → 3칸 = **앱 사용(−P, 관리·그 외) · 잠금 해제(±P) · 쉼(+P)**. 세 칸이 지수를 움직이는 요인 전부입니다. |
